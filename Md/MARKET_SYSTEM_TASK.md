# 포켓몬 슬롯머신 + 가상 투자 시스템 구현 작업지시서

## 1. 작업 목적

현재 포켓몬 슬롯머신 카드 수집 웹사이트에 다음 시스템을 추가/수정한다.

1. 슬롯머신 중복 카드 획득 시스템
2. TC 재화 시스템
3. 포켓몬 카드 시장 가격 시스템
4. 현실 시간 기반 Market Tick
5. 주식 시장 상태 알고리즘
6. 급등/급락 알고리즘
7. 선택적 가격 복원
8. 시장 뉴스 시스템
9. MARKET 화면
10. 카드 판매 및 자산 시스템

기존 슬롯머신 연출, 카드 데이터, COLLECTION 등 정상 동작하는 기능은 가능한 유지한다.

프레임워크를 새로 추가하지 않는다.

현재 프로젝트의 HTML / CSS / JavaScript 구조를 먼저 분석한 후 기존 구조를 최대한 재사용한다.

---

# 2. 작업 전 필수

코드를 수정하기 전에 프로젝트 전체를 확인한다.

특히 다음을 찾는다.

* 슬롯머신 실행 코드
* 일반 / 전설 / 환상 확률 계산 코드
* 당첨 카드 선택 코드
* 이미 획득한 카드를 후보에서 제외하는 코드
* 카드 COLLECTION 저장 구조
* localStorage 저장 구조
* 화면 전환 / Navigation 구조
* 포켓몬 데이터 구조
* 현재 카드 희귀도 데이터
* 슬롯 애니메이션 / 당첨 연출

기존 기능을 중복 구현하지 않는다.

필요하지 않은 대규모 리팩터링을 하지 않는다.

---

# 3. 재화

재화 이름:

`Trade Coin`

표시 단위:

`TC`

플레이어는 TC를 사용해서 슬롯머신을 돌리고 포켓몬 카드를 판매해서 TC를 획득한다.

---

# 4. 슬롯머신 비용 / 당첨 확률

## 일반

* 비용: `1,000 TC`
* 당첨 확률: `50%`

## 전설

* 비용: `25,000 TC`
* 당첨 확률: `20%`

## 환상

* 비용: `150,000 TC`
* 당첨 확률: `10%`

슬롯을 실행하기 전에 TC가 충분한지 검사한다.

부족하면 실행하지 않는다.

슬롯 실행이 시작될 때 비용을 차감한다.

---

# 5. 슬롯머신 중복 카드 규칙 변경

기존 규칙:

`이미 획득한 카드는 다시 슬롯 후보에 포함하지 않는다.`

이 규칙을 제거한다.

변경 후:

```text
희귀도 선택
↓
해당 희귀도의 전체 카드 Pool에서 랜덤 선택
↓
당첨
↓
처음 획득?
├─ YES → 도감 등록 + 보유 수량 1
└─ NO  → 기존 보유 수량 +1
```

이미 획득한 카드도 계속 슬롯머신에서 다시 나올 수 있어야 한다.

---

# 6. 도감과 보유량 분리

반드시 다음 두 데이터를 분리한다.

```text
discovered
quantity
```

예:

```text
뮤츠

discovered = true
quantity = 3
```

3장을 전부 판매하면:

```text
discovered = true
quantity = 0
```

도감 등록은 절대 취소되지 않는다.

같은 포켓몬 카드 여러 장을 각각 별도 객체로 저장하지 않는다.

가능하면 `cardId → quantity` 방식으로 관리한다.

---

# 7. 슬롯 기대값

슬롯머신 자체의 장기 기대값은 `100%`를 기준으로 한다.

공식:

```text
당첨 확률 × 평균 카드 가격
=
슬롯 1회 비용
```

따라서 카드 평균 가격 기준은 다음과 같다.

## 일반

```text
1,000 / 0.5
= 평균 2,000 TC
```

## 전설

```text
25,000 / 0.2
= 평균 125,000 TC
```

## 환상

```text
150,000 / 0.1
= 평균 1,500,000 TC
```

모든 카드가 같은 가격일 필요는 없다.

각 희귀도 내부에서 카드별 가격 차이는 허용하지만 전체 평균은 위 값에 가깝도록 구성한다.

---

# 8. 시장 가격 기본 구조

포켓몬 1025마리 각각 시장 데이터를 가진다.

필요한 핵심 정보:

```text
cardId
rarity

startingPrice
fairPrice
currentPrice

volatility

trend
trendStrength
trendRemaining

momentum

priceHistory
```

`startingPrice`

게임 최초 기준 가격.

`fairPrice`

현재 시장에서 장기적으로 형성되는 기준 가치.

`currentPrice`

현재 실제 시장 가격.

`fairPrice`는 영구 고정값이 아니다.

장기적으로 변할 수 있어야 한다.

---

# 9. Market Tick

현실 시간 기준:

`10분 = 1 Market Tick`

가격은 매 프레임 계산하지 않는다.

`Date.now()` 기반으로 현재 PC 시간을 사용한다.

마지막 시장 갱신 시간을 저장한다.

예:

```text
lastMarketUpdate = 12:00
현재 시간 = 12:37
```

이면:

```text
3 Tick 경과
```

로 판단한다.

12:10 / 12:20 / 12:30에 해당하는 시장 변화를 처리한다.

웹사이트가 꺼져 있던 시간도 경과 시간으로 인정한다.

---

# 10. 시간 조작

이 웹사이트는 개인용 가상 투자 시뮬레이션이다.

Windows 시간을 앞으로 변경해서 시장을 빠르게 진행시키는 것을 막지 않는다.

서버 시간 검증을 추가하지 않는다.

치트 방지 시스템을 만들지 않는다.

시간을 뒤로 변경한 경우 가격을 과거 상태로 되돌릴 필요는 없다.

음수 Tick이 발생하지 않도록 안전 처리한다.

---

# 11. 전체 시장 알고리즘

가격을 단순 개별 랜덤만으로 결정하지 않는다.

한 Tick의 기본 흐름:

```text
전체 시장 상태
↓
희귀도 시장 상태
↓
시장 뉴스 영향
↓
카드별 Trend / Momentum
↓
개별 랜덤 변동
↓
급등 / 급락 검사
↓
선택적 가격 복원
↓
FairPrice 장기 변화
↓
최종 CurrentPrice
```

---

# 12. 전체 시장 상태

전체 시장에는 최소 다음 상태가 존재한다.

```text
NORMAL
BULL
BEAR
SIDEWAYS
```

의미:

```text
NORMAL
일반적인 시장

BULL
상승 성향

BEAR
하락 성향

SIDEWAYS
횡보 성향
```

시장 상태를 매 Tick마다 무작위로 바꾸지 않는다.

한 번 만들어진 시장 상태가 여러 Tick 지속될 수 있도록 한다.

예:

`6~30 Tick`

정확한 수치는 코드 상수/설정값으로 쉽게 조정 가능하게 한다.

---

# 13. 희귀도 시장

전체 시장 아래에 각각 독립적인 시장 상태를 가진다.

```text
Normal
Legendary
Mythical
```

예:

```text
전체 시장 = SIDEWAYS

일반 = BEAR
전설 = BULL
환상 = SIDEWAYS
```

이런 상황이 가능해야 한다.

---

# 14. 카드별 Trend / Momentum

카드는 최근 움직임을 어느 정도 유지할 수 있다.

예:

```text
100000
→ 101000
→ 102000
```

최근 상승한 카드라면 다음 Tick에서도 상승할 가능성이 약간 높아질 수 있다.

하지만 상승했다고 다음 Tick 상승을 보장하면 안 된다.

Momentum은 가격 방향의 확률/강도에만 영향을 준다.

---

# 15. 희귀도별 일반적인 성격

## 일반

* 가격 낮음
* 평상시 변동성이 상대적으로 높음
* 투기적인 성격
* 매우 큰 급등 가능

## 전설

* 가격 높음
* 평상시 비교적 안정적
* 중간 수준의 급등/급락

## 환상

* 가격 매우 높음
* 평상시 가장 안정적
* 퍼센트 급등락은 상대적으로 작음
* 가격 자체가 높기 때문에 실제 TC 변화량은 매우 클 수 있음

---

# 16. 특수 급등 / 급락 범위

## 일반

급등:

`+10% ~ +500%`

급락:

`-10% ~ -80%`

단, `+10~500%`를 균등 랜덤으로 계산하면 안 된다.

큰 급등일수록 매우 낮은 확률이어야 한다.

일반 급등 발생 시 가중치 예시:

```text
70% → +10~50%
20% → +50~150%
8%  → +150~300%
2%  → +300~500%
```

필요하면 수치를 설정 데이터로 분리한다.

## 전설

급등:

`+10% ~ +50%`

급락:

`-10% ~ -30%`

## 환상

급등:

`+10% ~ +30%`

급락:

`-10% ~ -20%`

---

# 17. 급등 / 급락 방향

급등과 급락을 항상 50:50으로 결정하지 않는다.

다음 요소가 방향 확률에 영향을 줘야 한다.

```text
전체 시장 상태
희귀도 시장 상태
현재 Momentum
활성 시장 뉴스
```

예:

```text
강한 호재 시장

급등 확률 증가
급락 확률 감소
```

반대로 강한 악재에서는 급락 확률이 증가한다.

---

# 18. 가격 복원

가격 복원은 항상 발생하면 안 된다.

예:

```text
FairPrice = 100,000
CurrentPrice = 140,000
```

이라고 해도 반드시 100,000으로 돌아가지 않는다.

가능한 결과:

```text
복원
140k → 130k → 120k
```

또는

```text
횡보
140k → 142k → 139k
```

또는

```text
추가 상승
140k → 150k → 160k
```

모두 가능해야 한다.

가격과 FairPrice 차이가 커졌을 때만 복원 후보가 되고, 그 이후 확률적으로 복원 효과가 적용되도록 한다.

---

# 19. FairPrice

FairPrice도 장기적으로 움직인다.

예:

```text
100,000
→ 103,000
→ 108,000
```

급등 후 시장에서 새로운 가격대가 형성될 수도 있다.

따라서 가격 복원은 `StartingPrice`가 아니라 현재 `FairPrice`를 기준으로 판단한다.

---

# 20. 시장 뉴스 시스템

시장 뉴스는 현실 시간 기준으로 다음 시간대를 사용한다.

```text
아침
점심
저녁
```

각 시간대에서 뉴스가 랜덤으로 발생할 수 있다.

하루마다 같은 뉴스 조합이 반복되지 않도록 랜덤성을 가진다.

뉴스는 다음 대상을 가질 수 있다.

```text
전체 시장
일반
전설
환상
특정 포켓몬
```

뉴스 방향:

```text
호재
악재
중립
```

---

# 21. 뉴스의 핵심 원칙

뉴스가 가격을 직접 고정 변경하면 안 된다.

잘못된 예:

```text
전설 카드 호재 발생
→ 모든 전설 카드 즉시 +20%
```

사용하지 않는다.

뉴스는 기존 시장 알고리즘의 다음 값을 수정한다.

```text
상승 / 하락 Bias
변동성
급등 확률
급락 확률
Momentum 영향
```

예:

```text
전설 포켓몬 카드 수요 증가
```

결과:

```text
전설 카드 상승 성향 증가
전설 카드 변동성 약간 증가
전설 카드 급등 확률 증가
```

각 전설 카드의 실제 결과는 서로 달라야 한다.

---

# 22. 뉴스 예시

예:

```text
전설 포켓몬 카드 수집 열풍

Target = Legendary
Type = Positive
Strength = Normal
Duration = 6 Tick
```

다른 예:

```text
환상 포켓몬 카드 시장 과열 우려

Target = Mythical
Type = Negative
Strength = Major
Duration = 8 Tick
```

뉴스 텍스트는 실제 금융 뉴스처럼 자연스럽게 보이도록 작성한다.

---

# 23. 뉴스 지속시간

뉴스 효과는 여러 Tick 유지될 수 있다.

예:

```text
6 Tick
= 60분
```

뉴스 영향은 시간이 지나면서 점점 감소하는 구조를 지원한다.

예:

```text
100%
→ 80%
→ 60%
→ 40%
→ 20%
→ 종료
```

Decay 방식은 단순하고 조절 가능하게 구현한다.

---

# 24. 여러 뉴스 동시 적용

여러 뉴스가 동시에 활성화될 수 있다.

예:

```text
전체 시장 호재
+
전설 시장 악재
```

서로 영향을 상쇄할 수 있어야 한다.

단, 동일 뉴스가 무한 중첩되는 것은 막는다.

같은 News ID가 이미 활성 상태라면 다시 추가하지 않거나 갱신 방식으로 처리한다.

---

# 25. 뉴스 저장

페이지 새로고침 시 뉴스가 다시 랜덤 생성되면 안 된다.

현재 활성 뉴스와 생성된 시간대 뉴스는 저장한다.

가능하면 기존 저장 시스템을 재사용한다.

기본 저장은 `localStorage`를 사용한다.

---

# 26. 가격 기록

차트 표시용 가격 기록이 필요하다.

모든 데이터를 무한 저장하지 않는다.

최근 일정 개수만 유지한다.

초기 버전에서는 localStorage가 과도하게 커지지 않는 범위에서 제한한다.

필요 시 추후 IndexedDB로 이전할 수 있게 데이터 책임을 분리한다.

---

# 27. MARKET 메뉴 추가

기존 Navigation에:

```text
HOME
SLOT
MARKET
COLLECTION
SETTINGS
```

형태로 MARKET을 추가한다.

기존 웹사이트의 디자인 스타일은 유지한다.

현재의 파스텔 / 둥근 패널 / 카드 게임 분위기를 그대로 사용한다.

갑자기 검은색 증권사 UI로 전체 디자인을 변경하지 않는다.

정보 배치만 실제 주식 앱을 참고한다.

## 매도

초기 버전은 다음 두 기능만 구현한다.

```text
1장 매도
전체 매도
```

카드를 판매하면:

```text
quantity 감소
↓
현재 시장 가격만큼 TC 증가
```

전부 판매해도 discovered 상태는 유지한다.

# 29. MARKET에서 매수는 구현하지 않는다

MARKET의 카드 직접 구매 기능은 만들지 않는다.

카드 획득 방법은 슬롯머신이다.

```text
SLOT
→ 카드 획득

MARKET
→ 가격 확인 / 보유 / 판매
```

역할을 유지한다.

# 30. 전체 게임 핵심 루프

최종 플레이 흐름:

```text
TC 보유
↓
슬롯 비용 지불
↓
성공 / 실패
↓
카드 획득
↓
중복이면 보유량 증가
↓
MARKET 확인
↓
10분마다 가격 변동
↓
시장 뉴스 발생
↓
보유 / 판매 판단
↓
카드 판매
↓
TC 획득
↓
다시 슬롯
```

# 31. 성능 기준

1025개 카드 전체 Market Tick:

`O(n)`

카드 ID 검색:

가능하면 `Map` 또는 Key 기반 객체를 사용해서 `O(1)`.

보유 수량 검색:

`O(1)`.

DOM에서 매번 1025개 전체를 불필요하게 다시 렌더링하지 않는다.

Market Tick 계산을 `requestAnimationFrame`이나 매 프레임 실행하지 않는다.

# 33. 코드 구조

현재 프로젝트 구조를 먼저 분석하고 기존 파일을 재사용한다.

필요할 경우 역할 기준은 다음을 참고한다.

```text
Slot
- 슬롯 실행
- 비용 지불
- 확률
- 카드 획득

Collection
- discovered
- quantity

Market
- Market Tick
- 전체 시장
- 희귀도 시장
- 카드 가격

News
- 뉴스 생성
- 지속시간
- 시장 Modifier

Economy
- TC
- 총 자산
- 카드 판매

Storage
- localStorage 저장/로드
```

단, 이 이름 그대로 새 파일을 무조건 생성하지 않는다.

기존 시스템으로 해결 가능하면 기존 코드를 확장한다.

불필요한 클래스/파일 분리는 하지 않는다.

# 35. 반드시 테스트할 항목

## 슬롯

* TC 부족 시 슬롯 실행 불가
* 슬롯 비용 정확히 차감
* 실패 시 카드 미획득
* 당첨 시 카드 획득
* 동일 카드 중복 획득 가능
* 중복 시 quantity 증가
* 기존 카드가 슬롯 Pool에서 제거되지 않음

## COLLECTION

* 최초 획득 시 discovered 등록
* 카드 판매 후 quantity 0이어도 discovered 유지

## MARKET

* 현실 시간 10분마다 가격 변화
* 새로고침해도 현재 가격 유지
* 사이트를 닫았다 켜도 경과 Tick 처리
* 가격이 음수가 되지 않음
* FairPrice와 CurrentPrice가 분리되어 작동
* 가격 복원이 항상 발생하지 않음

## 급등/급락

* 일반 최대 +500% 가능
* +300~500%가 매우 드물게 발생
* 전설/환상 범위 준수
* 시장 상태와 뉴스가 급등/급락 방향에 영향

## 뉴스

* 아침/점심/저녁 기준 랜덤 뉴스
* 뉴스가 가격을 직접 고정 변경하지 않음
* 뉴스가 시장 알고리즘에 Modifier 형태로 영향
* 여러 뉴스 동시 적용 가능
* 동일 뉴스 무한 중첩 방지
* 새로고침해도 활성 뉴스 유지
* 지속시간 종료 후 정상 제거

## 판매

* 1장 판매 가능
* 전체 판매 가능
* 정확한 TC 지급
* quantity 감소
* discovered 유지

# 36. 금지 사항

* 기존 정상 기능을 이유 없이 삭제하지 않는다.

* MARKET에 카드 매수 기능을 추가하지 않는다.
* Git push 하지 않는다.
