# MARKET 전체 목록 거래 정렬 시스템 변경

## 작업 범위

이번 작업에서는 MARKET 화면 하단의 전체 포켓몬 목록 정렬 기능만 변경한다.

최종 정렬 기준은 아래 4개만 사용한다.

1. 거래대금
2. 거래량 높은순
3. 수익률 높은순
4. 수익률 낮은순

기존 정렬 항목인 아래 항목은 MARKET 전체 목록 정렬 Dropdown에서 제거한다.

- 가격순
- 10분 등락률순
- 보유량순

이번 작업과 관계없는 MARKET 기능은 수정하지 않는다.

시장 가격 계산 공식, 슬롯, 보유 포켓몬 평균 획득가, MARKET NEWS, 카드 판매, 가격 차트는 변경하지 않는다.

Git commit과 Git push는 실행하지 않는다.

# 2. 정렬 Dropdown 최종 항목

MARKET 전체 포켓몬 목록의 정렬 Dropdown은 아래 4개만 표시한다.

```text
거래대금
거래량 높은순
수익률 높은순
수익률 낮은순

기본 선택값은:

거래대금

으로 한다.

거래대금은 의미상:

최근 24시간 거래대금 높은순

이다.

UI에는 거래대금이라고만 표시한다.

3. 거래량 정의

거래량은 실제 플레이어가 사고판 카드 수가 아니다.

시장 시뮬레이션 내부에서 생성되는:

최근 24시간 가상 거래량

을 의미한다.

단위:

장

시장 가격이 갱신되는 기존 10분 Tick마다 각 포켓몬에 새로운 가상 거래량을 1개 생성한다.

이번 작업에서는 거래량 생성식을 복잡하게 만들지 않는다.

각 포켓몬의 10분 Tick 거래량은:

1 ~ 100

사이의 정수로 생성한다.

범위 양 끝을 포함한다.

예:

17장
63장
100장
1장

기존 프로젝트에 시장 계산에서 사용하는 랜덤 함수가 있으면 그 함수를 재사용한다.

별도의 랜덤 시스템을 만들지 않는다.

희귀도, 뉴스, 가격, 시장 상태에 따라 거래량 생성 확률을 다르게 만들지 않는다.

이번 작업에서는 모든 포켓몬에 동일한 1~100 생성 규칙을 적용한다.

4. 최근 24시간 거래량

시장은 10분마다 Tick이 발생한다.

1시간 = 6 Tick
24시간 = 144 Tick

따라서 포켓몬마다 최근 144개의 거래량만 유지한다.

최근 24시간 거래량:

최근 144 Tick의 거래량 합계

예:

08:00 = 50장
08:10 = 80장
08:20 = 30장

현재까지 거래량 = 160장

144 Tick을 초과한 거래량은 최근 24시간 계산에서 제외한다.

5. 거래대금 정의

거래대금은 다음 방식으로 계산한다.

Tick 거래대금
=
해당 Tick의 시장 가격 × 해당 Tick의 거래량

최근 24시간 거래대금:

최근 144 Tick의 Tick 거래대금 합계

예:

08:00
가격 1,000 TC
거래량 100장

Tick 거래대금
= 100,000 TC

08:10
가격 1,100 TC
거래량 80장

Tick 거래대금
= 88,000 TC

08:20
가격 1,050 TC
거래량 120장

Tick 거래대금
= 126,000 TC

최근 거래대금:

100,000
+ 88,000
+ 126,000

= 314,000 TC

거래대금 계산에:

현재가 × 24시간 총 거래량

공식을 사용하지 않는다.

각 Tick 당시의 가격을 사용한다.

6. Tick 가격 기준

거래대금 계산에 사용하는 Tick 가격은:

해당 10분 시장 Tick의 가격 계산이 완료된 후의 현재 가격

이다.

처리 순서:

10분 시장 Tick 시작
↓
기존 시장 가격 계산
↓
포켓몬 현재 가격 확정
↓
가상 거래량 생성
↓
Tick 거래대금 = 확정된 현재 가격 × Tick 거래량
↓
24시간 거래 데이터 기록

시장 가격 계산 순서는 변경하지 않는다.

7. 24시간 거래 데이터 저장 구조

포켓몬별 거래 데이터는 최대 144 Tick까지만 저장한다.

개념적인 구조:

trade24h: {
    volumes: [],
    amounts: [],
    head: 0,
    count: 0,
    volumeTotal: 0,
    amountTotal: 0
}

정확한 필드명은 현재 market.js 데이터 구조에 맞춰 짧고 명확하게 정한다.

새로운 클래스를 만들지 않는다.

8. 순환 버퍼

volumes와 amounts는 최대 144개까지만 유지한다.

145번째 Tick부터 가장 오래된 값을 삭제하기 위해 shift()를 반복하지 않는다.

고정 크기 순환 버퍼를 사용한다.

새 Tick 추가:

현재 저장 개수 < 144
→ 새 위치에 기록
→ count +1

현재 저장 개수 = 144
→ head 위치의 오래된 데이터 제거
→ 그 위치에 새 데이터 덮어쓰기
→ head 이동

오래된 데이터가 제거될 때:

volumeTotal
→ 오래된 거래량 차감

amountTotal
→ 오래된 거래대금 차감

그 후 새 데이터를 합계에 추가한다.

따라서 Tick 1회 처리에서 전체 144개 History를 다시 합산하지 않는다.

9. O(1) 거래 합계 갱신

새 Tick 거래량:

newVolume

새 Tick 거래대금:

newAmount

144개가 이미 저장되어 있다면:

volumeTotal
=
volumeTotal
- oldVolume
+ newVolume
amountTotal
=
amountTotal
- oldAmount
+ newAmount

방식으로 처리한다.

거래 데이터 Tick 추가는 O(1)이어야 한다.

10. 저장공간 제한

포켓몬 한 종류당 최대:

거래량 144개
거래대금 144개

만 저장한다.

게임을:

1일
7일
30일
1년

실행해도 거래 History 크기가 144 Tick을 초과하면 안 된다.

시간이 지나면서 localStorage 거래 History 크기가 계속 증가하면 안 된다.

11. 기존 세이브 데이터

기존 세이브에는 거래량 / 거래대금 History가 존재하지 않는다.

과거 거래량을 임의로 생성해서 소급 적용하지 않는다.

업데이트 후 최초 실행 시:

거래 History = 빈 상태
거래량 합계 = 0
거래대금 합계 = 0

에서 시작한다.

이후 시장 Tick이 발생하면서 데이터가 쌓인다.

기존 가격 History를 이용해 과거 거래량을 추정하지 않는다.

기존 세이브 데이터는 삭제하지 않는다.

현재 save migration 구조를 재사용한다.

필요하면 save version을 증가시킨다.

12. Offline Catch-up

기존 Offline Catch-up 시장 가격 진행은 유지한다.

Offline Catch-up에서도 최근 24시간에 해당하는 거래 데이터는 생성한다.

단, 거래 History는 최근 144 Tick만 필요하다.

예:

오프라인 기간 = 300 Tick

이라면 거래량 / 거래대금 History를 300 Tick 모두 저장하지 않는다.

최종적으로 최근:

144 Tick

만 남아야 한다.

기존 Offline Catch-up 루프를 불필요하게 두 번 실행하지 않는다.

시장 가격 계산을 위한 기존 Catch-up 흐름 안에서 처리한다.

거래 History가 필요한 범위보다 오래된 Tick의 거래 데이터를 별도로 저장하지 않는다.

15. 수익률 정의

MARKET 전체 목록의 수익률은 보유 포켓몬 평균 획득가를 사용하지 않는다.

전체 시장 포켓몬에 적용되는:

최근 24시간 가격 수익률

을 사용한다.

공식:

24시간 수익률
=
(현재 가격 - 24시간 기준 가격)
÷ 24시간 기준 가격
× 100
16. 24시간 기준 가격

기존 24시간 가격 History 순환 버퍼를 사용한다.

새 가격 History를 만들지 않는다.

가격 History가 정확히 144 Tick 이상 존재하면:

최근 24시간 범위에서 가장 오래된 가격

을 기준 가격으로 사용한다.

가격 History가 아직 144 Tick 미만이면:

현재 존재하는 History 중 가장 오래된 가격

을 기준으로 사용한다.

유효한 가격이 1개뿐이면:

수익률 = 0.00%

로 처리한다.

기준 가격이:

0
undefined
NaN
Infinity

이면 나눗셈을 실행하지 않고 0.00%로 처리한다.

20. 정렬 대상

수익률이 같은 경우도 동일하다.

불필요한 추가 정렬 기준을 만들지 않는다.

거래대금 50,000

거래량 70
거래대금 84,000

합계는:

기존 거래량 합계 - 50 + 70
기존 거래대금 합계 - 50,000 + 84,000

결과와 일치해야 한다.

전체 144개 배열을 다시 합산하지 않는다.
