# MARKET 보유 포켓몬 영역 추가

## 작업 범위

이번 작업에서는 MARKET 화면에 아래 기능만 추가한다.

1. 현재 보유 중인 포켓몬 목록 UI 추가
2. 포켓몬별 평균 획득가 저장
3. 평균 획득가 기준 수익률 계산
4. 가격 높은순 정렬
5. 수익률 높은순 정렬
6. 기존 세이브 데이터 자동 보정
7. 시장 가격 변경 시 현재가와 수익률 자동 갱신

이 작업과 관계없는 기능은 수정하지 않는다.

다음 기능은 기존 동작을 그대로 유지한다.

- 시장 가격 계산식
- 10분 시장 Tick
- 시장 상태 계산
- 급등 / 급락
- Momentum
- 변동성
- 가격 History
- 24시간 / 7일 순환 버퍼
- 장기 최고가 / 최저가 / 평균가
- MARKET NEWS
- 슬롯 확률
- 슬롯 애니메이션
- 포켓몬 데이터
- 가격 차트 계산
- 기존 카드 판매 금액 계산
- 도감
- MARKET 하단 전체 포켓몬 목록
- MARKET 검색 / 희귀도 필터 / 기존 정렬 기능

Git commit과 Git push는 실행하지 않는다.

# 2. MARKET 화면 배치

현재 상단의 아래 3개 자산 카드는 그대로 유지한다.

```text
총 자산
보유 TC
보유 카드 평가액

이 3개 카드 바로 아래에 새로운 현재 보유 중인 포켓몬 영역을 추가한다.

PC 화면의 구조는 다음과 같다.

┌─────────────────────────────────────┬──────────────────┐
│ 현재 보유 중인 포켓몬                │ MARKET NEWS      │
│                                     │                  │
│ [가격 높은순] [수익률 높은순]         │ 기존 뉴스 내용     │
│                                     │                  │
│ 보유 포켓몬 목록                      │                  │
└─────────────────────────────────────┴──────────────────┘

┌─────────────────────────────────────┐
│ 기존 선택 포켓몬 상세                 │
│ 기존 가격 차트                       │
│ 기존 1장 매도 / 전체 매도             │
└─────────────────────────────────────┘

정확한 위치:

상단 자산 카드 3개
↓
현재 보유 중인 포켓몬 + MARKET NEWS
↓
기존 선택 포켓몬 상세 / 가격 차트
↓
기존 MARKET 하단 포켓몬 전체 목록

기존 선택 포켓몬 상세 카드의 내부 구조는 변경하지 않는다.

기존 MARKET NEWS의 내부 동작과 데이터도 변경하지 않는다.

3. 모바일 배치

모바일에서는 가로 2열을 강제로 유지하지 않는다.

다음 순서로 세로 배치한다.

현재 보유 중인 포켓몬
↓
MARKET NEWS
↓
기존 포켓몬 상세 / 차트
↓
기존 MARKET 전체 목록

가로 스크롤이 발생하면 안 된다.

기존 반응형 breakpoint를 우선 재사용한다.

4. 보유 포켓몬 목록 대상

현재 보유 수량이 1장 이상인 포켓몬만 표시한다.

보유 수량 >= 1
→ 표시

보유 수량 = 0
→ 표시하지 않음

같은 포켓몬을 여러 장 보유하고 있어도 목록에는 한 번만 표시한다.

예:

이상해씨 ×3
파이리 ×2
뮤 ×1

포켓몬 카드 1장마다 별도의 목록 항목을 만들지 않는다.

5. 보유 포켓몬 항목 표시 정보

각 항목에는 아래 정보만 표시한다.

포켓몬 이미지
포켓몬 이름
보유 수량
평균 획득가
현재 시장 가격
수익률

예:

[포켓몬 이미지]

이상해씨 ×3

평균 획득가  1,033 TC
현재가      1,100 TC
수익률       +6.45%

기존 프로젝트의 포켓몬 이미지 경로와 이름 데이터를 그대로 사용한다.

가격 표시는 기존 TC 가격 포맷 함수가 있으면 반드시 재사용한다.

6. 평균 획득가의 의미

평균 획득가는 슬롯을 돌릴 때 사용한 TC 비용이 아니다.

슬롯에서 포켓몬이 당첨된 순간의 해당 포켓몬 현재 시장 가격을 획득 가격으로 사용한다.

예:

슬롯 사용 비용 = 500 TC
당첨된 이상해씨 현재 시장 가격 = 1,200 TC

이 경우:

평균 획득가 = 1,200 TC

이다.

500 TC

를 평균 획득가로 사용하지 않는다.

7. 평균 획득가 저장 데이터

각 포켓몬의 기존 보유 데이터에 평균 획득가 값을 추가한다.

개념적으로 필요한 값:

포켓몬 ID
보유 수량
평균 획득가

개별 카드 획득 가격 History는 만들지 않는다.

다음과 같은 배열을 만들지 않는다.

[1000, 1200, 900, 1100 ...]

평균 획득가 값 1개만 유지한다.

8. 첫 번째 카드 획득

현재 보유 수량이 0인 포켓몬을 슬롯에서 처음 획득하면:

기존 보유 수량 = 0

당첨 순간 이미 존재하는 현재 시장 가격을 가져온다.

예:

현재 이상해씨 시장 가격 = 1,000 TC

처리:

보유 수량 = 1
평균 획득가 = 1,000

시장 가격을 새로 계산하지 않는다.

market.js에 이미 계산되어 있는 현재 가격을 사용한다.

9. 같은 포켓몬 추가 획득

같은 포켓몬을 다시 획득하면 기존 평균 획득가와 기존 보유 수량을 이용해 O(1)로 새 평균을 계산한다.

공식:

새 평균 획득가
=
(기존 평균 획득가 × 기존 보유 수량 + 당첨 순간 현재 시장 가격)
÷
(기존 보유 수량 + 1)

예:

기존 보유 수량 = 2
기존 평균 획득가 = 1,100 TC
새 카드 당첨 순간 현재가 = 900 TC

계산:

(1,100 × 2 + 900) ÷ 3
= 1,033.333...

결과:

보유 수량 = 3
평균 획득가 = 1,033.333...

기존 보유 카드 전체를 탐색해서 평균을 다시 계산하지 않는다.

10. 평균 획득가 숫자 처리

평균 획득가 내부 데이터는 JavaScript Number 값으로 유지한다.

계산 결과:

1033.333333...

처럼 소수점이 존재해도 내부 값은 그대로 유지한다.

화면에 표시할 때만 기존 TC 표시 방식에 맞춰 반올림한다.

화면 표시용으로 반올림된 값을 다음 평균 계산에 다시 사용하지 않는다.

11. 수익률 계산

수익률 공식은 다음 하나만 사용한다.

수익률
=
(현재 시장 가격 - 평균 획득가)
÷ 평균 획득가
× 100

예:

평균 획득가 = 1,000
현재 시장 가격 = 1,100

결과:

+10.00%

화면에는 소수점 둘째 자리까지 표시한다.

12. 수익률 예외 처리

다음 경우에는 나눗셈을 실행하지 않는다.

평균 획득가 <= 0
평균 획득가가 Number가 아님
평균 획득가가 유효하지 않음

NaN 또는 Infinity가 UI에 표시되면 안 된다.

13. 수익률 색상

수익률이 0보다 크면:

+6.45%

빨간색으로 표시한다.

수익률이 0보다 작으면:

-5.20%

파란색으로 표시한다.

수익률이 정확히 0이면:

0.00%

기본 텍스트 색상을 사용한다.

기존 프로젝트에서 가격 상승과 하락에 사용하는 빨간색 / 파란색 CSS가 있으면 그대로 재사용한다.

새로운 상승 / 하락 색상은 만들지 않는다.

14. 시장 10분 Tick 처리

시장 가격은 기존 시스템대로 10분마다 변경한다.

10분 Tick에서는 평균 획득가를 변경하지 않는다.

처리 순서:

10분 시장 Tick
↓
기존 시장 가격 계산
↓
현재 시장 가격 변경
↓
보유 포켓몬 목록 UI 갱신
↓
각 포켓몬 현재가 다시 표시
↓
각 포켓몬 수익률 다시 계산
↓
현재 선택된 정렬 기준으로 목록 재정렬

시장 가격 계산식을 이번 작업에서 수정하지 않는다.

15. 1장 매도

기존 1장 매도 기능의 가격 계산과 TC 지급 방법은 변경하지 않는다.

1장을 매도한 후:

보유 수량 -1

을 처리한다.

남은 보유 수량이 1 이상이면 평균 획득가는 변경하지 않는다.

예:

기존:
이상해씨 ×3
평균 획득가 = 1,033 TC

1장 매도:

이상해씨 ×2
평균 획득가 = 1,033 TC

개별 카드의 획득 가격을 추적하지 않는다.

16. 마지막 1장 매도

1장 매도 후 보유 수량이 0이 되면:

보유 수량 = 0
평균 획득가 = 초기화

한다.

보유 목록에서도 해당 포켓몬을 즉시 제거한다.

다음에 같은 포켓몬을 다시 획득하면 새로운 첫 획득으로 처리한다.

17. 전체 매도

기존 전체 매도의 가격 계산과 TC 지급 방식은 변경하지 않는다.

전체 매도 완료 후:

보유 수량 = 0
평균 획득가 = 초기화

한다.

해당 포켓몬은 보유 포켓몬 목록에서 제거한다.

18. 기존 세이브 데이터 자동 보정

기존 세이브에는 다음 상태가 존재할 수 있다.

보유 수량 > 0
평균 획득가 데이터 없음

이 경우 과거 실제 획득 가격을 추정하지 않는다.

현재 시장 가격을 평균 획득가 초기값으로 사용한다.

예:

기존 이상해씨 보유 수량 = 3
현재 시장 가격 = 1,250 TC
평균 획득가 데이터 없음

자동 보정:

보유 수량 = 3
평균 획득가 = 1,250 TC

최초 수익률:

0.00%
19. 기존 세이브 보정 시점

시장 현재 가격 데이터가 정상적으로 로드된 이후에 보정한다.

현재 시장 가격을 사용할 수 없는 시점에 임의의 값을 저장하지 않는다.

이미 평균 획득가가 존재하는 포켓몬은 값을 덮어쓰지 않는다.

조건:

보유 수량 > 0
AND
평균 획득가 없음

일 때만 초기화한다.

현재 프로젝트의 save version / migration 시스템이 있다면 기존 방식을 재사용한다.

필요하다면 save version을 증가시킨다.

새로운 별도 migration 시스템은 만들지 않는다.

20. 현재 보유 중인 포켓몬 제목

새 영역 제목:

현재 보유 중인 포켓몬

제목 바로 아래에 정렬 버튼 2개를 배치한다.

[가격 높은순] [수익률 높은순]
21. 가격 높은순

가격 높은순 버튼을 누르면 보유 포켓몬을 현재 시장 가격 기준으로 내림차순 정렬한다.

기준은:

포켓몬 카드 1장의 현재 시장 가격

이다.

예:

A = 100,000 TC
B = 20,000 TC
C = 50,000 TC

화면:

A
C
B

다음 값을 기준으로 정렬하지 않는다.

현재가 × 보유 수량
총 보유 평가액
평균 획득가
포켓몬 번호
22. 수익률 높은순

수익률 높은순 버튼을 누르면 평균 획득가 기준 수익률을 내림차순 정렬한다.

예:

A = -5.00%
B = +20.00%
C = +3.00%
D = 0.00%

화면 순서:

B
C
D
A

가장 높은 수익률이 맨 위에 위치한다.

23. 기본 정렬 상태

MARKET 화면을 처음 열었을 때 기본 정렬은:

가격 높은순

으로 한다.

정렬 상태를 localStorage에 따로 저장하지 않는다.

MARKET 화면을 새로 열었을 때 가격 높은순으로 시작해도 된다.

24. 정렬 버튼 활성 상태

두 정렬 버튼 중 하나만 활성 상태로 표시한다.

기본:

가격 높은순 = 활성
수익률 높은순 = 비활성

수익률 버튼 클릭:

가격 높은순 = 비활성
수익률 높은순 = 활성

기존 MARKET의 버튼 스타일을 재사용한다.

새 디자인 시스템을 만들지 않는다.

25. 10분 Tick 이후 정렬 유지

사용자가 수익률 높은순을 선택한 상태라고 가정한다.

시장 가격이 10분 Tick으로 변경되면:

현재 가격 변경
↓
각 수익률 다시 계산
↓
수익률 높은순으로 다시 정렬

한다.

Tick 발생 후 정렬 기준을 가격 높은순으로 되돌리지 않는다.

현재 MARKET 화면이 열려 있는 동안 사용자가 선택한 정렬 기준을 유지한다.

26. 정렬 구현 방법

이번 보유 목록은 최대 포켓몬 종류 수인 1,025개 이하이다.

정렬 실행 시점도 다음으로 제한된다.

MARKET 최초 표시
정렬 버튼 클릭
10분 시장 Tick
포켓몬 획득
포켓몬 매도

따라서 이번 기능에 한해서 JavaScript 기본:

.sort()

사용을 허용한다.
